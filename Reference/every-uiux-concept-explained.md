## 1. Affordances & Signifiers (0:00)

**Affordance**: 어떤 오브젝트가 어떻게 사용될 수 있는지를 암시하는 특성.
**Signifier**: 그 affordance를 사용자에게 알려주는 시각적 단서.

- 버튼이 눌릴 수 있다는 걸 암시하는 입체감, 색상, 그림자 → signifier
- 클릭 가능한 요소는 커서가 바뀌거나, 호버 시 색이 바뀌어야 함
- 잘 설계된 UI는 "어떻게 쓰는지" 설명 없이도 직관적으로 사용 가능해야 함

---

## 2. Visual Hierarchy (0:45)

사용자의 시선을 의도적으로 유도하는 레이아웃 원칙.

| 요소 | 역할 |
|------|------|
| 크기 | 크면 먼저 보임 |
| 굵기(Weight) | Bold = 중요 |
| 색상 대비 | 고대비 = 시선 집중 |
| 공백 | 요소 간 관계를 암시 |
| 위치 | 상단/좌측이 먼저 읽힘 |

- 모든 요소를 같은 크기/굵기로 만들면 계층이 사라짐 → 사용자가 무엇을 먼저 봐야 할지 모름
- 제목 → 부제 → 본문 → CTA 순으로 시각적 무게감을 다르게 설정

---

## 3. Grids, Layouts & Spacing (2:04)

일관된 레이아웃 시스템으로 정렬감과 신뢰감을 만드는 원칙.

- **Grid**: 콘텐츠를 정렬하는 보이지 않는 구조. 보통 12컬럼 기준
- **Spacing 시스템**: 4px 또는 8px 배수 사용 (8, 16, 24, 32, 48…)
- **Padding vs Margin**: 내부 여백(padding)과 외부 여백(margin)을 일관되게 유지
- 연관된 요소는 가까이, 관련 없는 요소는 멀리 → **Proximity 원칙**
- 여백은 낭비가 아님 — 콘텐츠에 숨을 줌

---

## 4. Typography & Font Sizing (3:16)

텍스트는 디자인의 대부분을 차지 — 읽히는 텍스트를 만드는 원칙.

- **Type Scale**: 정해진 사이즈 단계 사용 (12, 14, 16, 20, 24, 32, 48…)
- **Line Height**: 본문은 폰트 크기의 1.4~1.6배가 적절
- **Letter Spacing**: 제목은 살짝 좁게, 영문 대문자는 넓게
- **폰트 수**: 한 디자인에 2개 이상 쓰지 말 것 (보통 1~2개)
- **가독성**: 본문 폰트는 최소 16px, 대비 비율 4.5:1 이상 (WCAG 기준)
- 강조는 Bold 또는 크기 차이로 — 무분별한 이탤릭/색상 혼용 금지

---

## 5. Color Theory (4:55)

색상이 감정, 행동, 계층을 어떻게 전달하는지.

- **Primary color**: 핵심 브랜드 색. CTA, 주요 인터랙션에 사용
- **Neutral colors**: 배경, 텍스트, 테두리 — 대부분의 면적 차지
- **Semantic colors**: 상태 전달 (초록 = 성공, 빨강 = 에러, 노랑 = 경고)
- 색상은 적을수록 강함 — 많이 쓸수록 계층이 무너짐
- 색상만으로 정보를 전달하지 말 것 (색맹 접근성 고려)

---

## 6. Dark Mode (5:47)

단순히 색을 반전하는 게 아닌, 별도 설계가 필요한 모드.

- 순수 검정(#000000) 대신 다크 그레이(#121212~#1E1E1E) 배경 사용
- Light에서의 그림자 → Dark에서는 elevation으로 표현 (밝은 레이어)
- 색상 채도는 Dark Mode에서 낮춰야 눈이 편함
- 동일한 색상이 Light/Dark에서 다르게 보이므로 토큰 기반 시스템 필요

---

## 7. Shadows (6:19)

그림자는 깊이감과 계층을 전달하는 도구.

- 그림자가 강할수록 요소가 앞에 있는 것처럼 보임
- **Blur 반경**: 작으면 선명하고 가까운 느낌, 크면 멀고 부드러운 느낌
- **Y 오프셋**: 빛이 위에서 온다는 자연스러운 시뮬레이션
- 모달/카드/버튼에 따라 그림자 강도를 다르게 설정
- 너무 많은 그림자 = 혼란스러운 계층 → 필요한 곳에만 적절히

---

## 8. Icons & Buttons (6:53)

인터랙션을 유도하는 핵심 UI 요소.

**Icons:**
- 의미가 명확한 아이콘만 사용 (범용 인지 가능한 것)
- 애매한 아이콘에는 라벨 병행
- 아이콘 세트 통일 (두꺼운 선과 얇은 선 혼용 금지)

**Buttons:**
- Primary / Secondary / Tertiary 버튼 계층 구분
- 충분한 클릭 영역 확보 (최소 44×44px — Apple HIG 기준)
- 텍스트는 버튼 액션을 명확히 설명 ("확인" < "파일 저장")

---

## 9. Feedback & States (7:29)

사용자 액션에 반응하는 UI 상태 설계.

모든 인터랙티브 요소는 다음 상태를 가져야 함:

| State | 설명 |
|-------|------|
| Default | 기본 상태 |
| Hover | 마우스 올린 상태 |
| Active / Pressed | 클릭 중인 상태 |
| Focused | 키보드 포커스 상태 |
| Disabled | 비활성화 상태 |
| Loading | 처리 중 상태 |
| Error | 오류 상태 |
| Success | 완료 상태 |

- 피드백이 없으면 사용자는 "작동하는지 모름" → 불안감, 반복 클릭

---

## 10. Micro Interactions (8:07)

UX 품질을 결정하는 작은 디테일들.

- 버튼 클릭 시 살짝 눌리는 애니메이션
- 토글 스위치의 부드러운 전환
- 폼 제출 성공 시 체크마크 애니메이션
- 스크롤에 따른 헤더 변화
- 목적: 사용자에게 즐거움 + 행동 확인 피드백 동시 제공
- 과하면 오히려 방해 — 짧고(200~400ms), 목적이 분명해야 함

---

## 11. Overlays (8:36)

콘텐츠 위에 레이어를 올려 집중을 유도하는 패턴.

- **Modal**: 중요한 결정/입력 요구. 배경 딤처리(overlay)
- **Drawer/Sheet**: 사이드나 하단에서 슬라이드 — 컨텍스트 유지
- **Tooltip**: 간단한 설명. 호버/탭으로 표시, 자동으로 사라짐
- **Toast/Snackbar**: 짧은 알림. 액션 방해 없이 상단/하단에 표시
- 오버레이 남용 = 사용자 흐름 차단 → 꼭 필요한 곳에만

---

## 핵심 요약

> 좋은 UI는 사용자가 UI를 의식하지 못하게 만든다.
> 모든 개념은 결국 하나로 수렴 — **사용자가 헤매지 않게**.

- 계층, 정렬, 여백 → 정보 구조
- 색상, 타이포, 그림자 → 감정과 깊이
- 상태, 피드백, 마이크로인터랙션 → 신뢰와 반응성
